# 2026-09-09 — v2.1: article-input mode

Branch: `v2.1-article-input` (off the committed v2 on `main`).

## What changed

Added a front-end so a user can submit a whole article instead of a claim
string: "I'll give you an article, you find the source and analyse it."

- **Claim Extractor agent** (`agents/claim_extractor.py`) — identifies the
  article's publishing outlet (`tools/source_id.py`) and extracts the primary
  checkable claim (LLM, with a headline-heuristic fallback). Writes a
  `source_docs` row keyed by the extracted claim's id.
- **`tools/source_id.py`** — URL / byline / credit → outlet, via the bias
  table. Pure/offline; parses a URL, never fetches it.
- **`graph.py`** — factored invoke into `_invoke_graph`; added
  `run_article_pipeline` alongside `run_pipeline`. The 5-agent graph itself is
  unchanged.
- **Bias/Blindspot Analyzer** — folds the submitting outlet into the L/C/R
  spread; new "no independent outlet corroborates this" blindspot.
- **Writer** — deterministic **Source of the submitted article** section
  prepended when a `source_docs` row exists.
- **Console** — `claim_extractor` row (article mode only) + "Submitted src"
  blackboard line.
- CLI: `--article [PATH]` (`-`=stdin, bare=sample), `--article-text`,
  `--article-url`.
- `store.py` — `source_docs` table + `SourceDoc` + write/get.
- `demo/fixtures.py` — Claim Extractor branch; `resources/sample_article.txt`.
- 15 new tests (59 total, still fully offline).

## Decisions made (and why)

- **New agent, not a graph rewrite.** The extracted primary claim *is* a claim;
  feeding it into the existing `build_graph` keeps every downstream agent,
  the cache, and the audit log identical between the two modes. Two thin entry
  points (`run_pipeline` / `run_article_pipeline`) share `_invoke_graph`.
- **"Find the source" = identify the publisher, not resolve provenance.** URL →
  domain is solid; byline/credit is a substring match against known outlet
  names. It explicitly does *not* fetch the URL (offline constraint) and can't
  detect syndicated wire copy under a local masthead. Flagged in HANDOFF so
  nobody builds trust logic on `origin_method == "byline"` as-is.
- **Deterministic source section in the report.** The Writer prepends the
  "Source of the submitted article" block from the `source_docs` row directly,
  not via the LLM — same pattern as the audit trail — so the headline feature
  output is always present and accurate.
- **Origin outlet joins the bias spread** (deduped by domain). It published the
  article, so it's a real data point; the more important output is the
  "only the submitting outlet carries this" blindspot when there's no
  independent coverage.
- **One primary claim per article.** Secondary claims are recorded in
  `source_docs` but not run — multi-claim fan-out is a future call, not this
  session's scope.
- **Article mode skips the report-cache pre-check.** The `claim_id` isn't known
  until extraction; running the full pipeline every time is acceptable for
  v2.1 and the report is still cached for later claim-mode hits.
