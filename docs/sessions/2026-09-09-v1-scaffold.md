# 2026-09-09 — v1 scaffold

## What changed

Initial build of the project from the resource document. Set up git, chose a
tech stack, and implemented the smallest 2-agent slice of the full 5-agent
design: Source-Finder + Cross-Checker, sharing state via a SQLite blackboard,
orchestrated with LangGraph. Full docs scaffold (README, CHANGELOG,
ARCHITECTURE, HANDOFF, this session-log convention) set up alongside the code
so the project is easy to pick back up across sessions/agents.

## Decisions made (and why)

- **LangGraph over AutoGen/CrewAI** for orchestration — the resource doc's own
  research flagged LangGraph's typed `State` as the most controllable fit for
  the blackboard pattern; AutoGen and CrewAI were both flagged as weaker fits
  for genuine shared state.
- **GDELT over NewsAPI** for the news source — no API key required, non-US
  centric coverage (relevant given the Indian-news angle in the brief), and
  ships tone data usable later as a cheap bias signal.
- **SQLite over any external DB** — zero infra, and it's what every reference
  repo in the resource doc used for the same "cache checked claims" need.
- **Source-Finder + Cross-Checker chosen as the 2 v1 agents**, over
  Source-Finder+Opposition or Source-Finder+Writer — full reasoning in
  `docs/ARCHITECTURE.md`. Short version: this pair is the smallest one that
  both demonstrates the shared-memory architecture *and* produces a real,
  inspectable verdict rather than a stub.
- **Verdict vocabulary constrained to corroborated/disputed/unverifiable** —
  directly from the resource doc's governance rule against single-source
  "false" verdicts.
- API keys were not provided this session (user chose to stub them via env
  vars) — so nothing here has been run against live GDELT/Anthropic APIs.
  Only mocked tests have been run. Flagged clearly in `docs/HANDOFF.md`.
