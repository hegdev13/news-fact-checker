## What v2.1 adds

**Article-input mode** — submit a whole article instead of a claim string:

- A new **Claim Extractor** agent runs first (article mode only). It:
  1. **finds the source** — identifies the article's publishing outlet from an
     accompanying URL, a URL in the body, or a byline / "(Reuters)"-style
     credit, and looks up its bias/factuality;
  2. **extracts the checkable claim** — one LLM call pulls out the central
     verifiable claim (+ up to two secondary claims).
- The extracted primary claim then runs through the **unchanged** 5-agent
  pipeline (Source-Finder ∥ Opposition → Cross-Checker → Bias/Blindspot →
  Writer + deep-research loop).
- The **Bias/Blindspot Analyzer** folds the submitting outlet into the L/C/R
  spread and flags "no independent outlet corroborates the submitted article"
  when only that outlet carries the story.
- The **Writer** report leads with a deterministic **Source of the submitted
  article** section.
- Everything stays visible in the live terminal dashboard (a "Claim Extractor"
  row + a "Submitted src" blackboard line appear in article mode) and in the
  `audit_log`.

## Setup

```bash
cd news-fact-checker
/opt/homebrew/bin/python3.11 -m venv .venv   # Python 3.11 required; adjust path if needed

.venv/bin/pip install -e ".[dev]"          # core + pytest
.venv/bin/pip install -e ".[dev,nvidia]"   # + openai SDK (needed for NVIDIA NIM provider)
```

> **macOS note:** `python` is not aliased by default and `python3` may point to
> system Python 3.9 (incompatible). Always use `.venv/bin/python` directly, or
> `source .venv/bin/activate` first to put the venv on your PATH.

## Environment / API keys

Copy `.env.example` to `.env` and fill in real values (`.env` is gitignored):

```bash
cp .env.example .env
```

Key variables:

| Variable | Purpose |
|---|---|
| `NEWSFACT_LLM_PROVIDER` | `anthropic` (default) or `nvidia` |
| `NVIDIA_API_KEY` | NVIDIA NIM key — get one at https://build.nvidia.com |
| `ANTHROPIC_API_KEY` | Anthropic key (if using Claude) |
| `NEWSFACT_MODEL` | Override model (auto-defaults per provider) |
| `NEWSFACT_DB_PATH` | SQLite blackboard path (default: `data/newsfact.db`) |
| `NEWSFACT_BIAS_TABLE` | Path to a custom outlet bias JSON (optional) |

Default models: `mistralai/mistral-large-2-instruct` (nvidia) · `claude-sonnet-4-5` (anthropic).

## Commands

### Demo mode (fully offline — no keys, no network)

```bash
.venv/bin/python -m newsfact.main --demo                    # 3 bundled claims, live dashboard
.venv/bin/python -m newsfact.main --demo --plain            # flat event trace (pipe-friendly)
.venv/bin/python -m newsfact.main --demo --json             # + machine-readable JSON recap
.venv/bin/python -m newsfact.main --demo --article          # bundled sample article (article mode)
.venv/bin/python -m newsfact.main --demo --article --plain  # article mode, flat trace
```

### Claim mode (live — requires API key)

```bash
.venv/bin/python -m newsfact.main "Your claim here"
.venv/bin/python -m newsfact.main "Claim one" "Claim two" "Claim three"
.venv/bin/python -m newsfact.main --file path/to/claims.txt   # one claim per line, # comments ok
.venv/bin/python -m newsfact.main --no-cache "claim"           # skip the report cache, re-run
```

### Article mode (live — requires API key)

```bash
.venv/bin/python -m newsfact.main --article path/to/article.txt
.venv/bin/python -m newsfact.main --article-text "Full article text here..."
.venv/bin/python -m newsfact.main --article - --article-url https://outlet.example/story  # stdin
```

### Tests (always offline — mocked GDELT + LLM, no keys needed)

```bash
.venv/bin/pytest                                           # full suite (59 tests)
.venv/bin/pytest tests/test_graph_v2.py                   # one file
.venv/bin/pytest -k "opposition or bias"                  # by keyword
.venv/bin/pytest tests/test_graph_v2.py::test_deep_research_loop_fires_on_low_confidence_disputed
```
